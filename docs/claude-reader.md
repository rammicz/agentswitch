# Claude Code reader

`ClaudeSessionAdapter` implements the read-only `SessionAdapter` contract separately from CLI integration and provider launch. It needs Node >=22.15, uses built-in filesystem APIs and never invokes Claude, reads account/settings files or calls a provider.

```ts
import { ClaudeSessionAdapter } from './adapters/index.js';
const reader = new ClaudeSessionAdapter({
  root: '/explicit/claude-config',
  onDiagnostic: diagnostic => console.error(diagnostic.code),
});
const sessions = await reader.discover();
const history = await reader.readHistoryDetailed(sessions[0]!.nativeId);
```

Explicit `root` denotes the Claude configuration directory containing `projects/`. It overrides nonempty `CLAUDE_CONFIG_DIR`, then `<home>/.claude`; `home` defaults to the OS home and `env` can replace environment resolution. Only direct UUID `.jsonl` files in immediate project buckets are considered. Subagent, orphaned/superseded, memory and tool-result directories are not traversed. Nested file/bucket symlinks are rejected; an explicitly selected root alias is canonicalized and file opens check canonical containment with read-only handles. This is the same bounded filesystem policy as the Codex reader, not an adversarial filesystem snapshot transaction.

`discover()` streams metadata and returns empty `messages`. It never builds a normalized transcript. `readHistory()` lazily projects public content; `readHistoryDetailed()` adds `complete` and safe diagnostics. Operations on one adapter are serialized and refresh the catalog, so appends and reverts are visible without reconstructing the reader. Discovery reads bounded metadata windows rather than whole transcripts, so total store size does not hide sessions, and every selected history read has its own byte budget, so sibling sessions never truncate it. Lower `limits` to bound work further.

Native session identity comes from the UUID filename, normalized to lowercase. An explicit mismatching `sessionId` is rejected record by record. Duplicate files retain one identity: newest usable file by mtime wins, with lexical bucket/file ordering breaking equal-mtime ties and an `unsupported-shape` metadata warning. Duplicate message UUIDs retain the first usable record and mark history incomplete. `id` is `claude:<nativeId>`. History IDs include the native message UUID and original block/result-part positions, preserving identity across hidden-block omissions, repeated reads and appends.

Workspace comes from the first valid absolute top-level recorded `cwd` on a supported graph entry. Existing folders resolve through `realpath` and Unicode NFC; missing folders retain their absolute recorded path with `workspace-unavailable`. Missing/relative cwd omits the session with `metadata-unavailable`; bucket names and process cwd never invent a source workspace. Folder consumers must compare exact canonical workspace identity, excluding child folders and sibling worktrees. Titles use the last recorded `customTitle`, then `aiTitle`, `lastPrompt`, `summary`, then first real public prompt, then a generated native-ID title. Discovery reads a head, checked every 64 KiB until the workspace and first real prompt are found and at most one maximal line past the first 64 KiB, plus the last 64 KiB, where Claude Code appends title updates. When the two meet, the tail resumes where the head stopped, so files up to about 128 KiB are read whole; in larger files, title records only in the skipped middle are not seen. Empty title updates clear the earlier field before that precedence is applied. Metadata is parsed only from supported top-level records, so nested tool fields cannot spoof it. Title metadata is bounded to 500 characters and first-prompt fallback to 200. `createdAt` is the first valid graph timestamp, falling back to mtime; `updatedAt` is file mtime. Sessions sort newest first, then normalized ID. A well-formed optional `producerVersion` is exposed when recorded.

The active conversation follows the native UUID/parent graph, preferring the latest main user/assistant leaf by file position, including ancestry behind terminal progress/system records. It recovers parallel assistant blocks belonging to the same native `message.id` and textual results matched through native parent, `sourceToolAssistantUUID` and unambiguous tool-call identity, respecting writer boundaries and avoiding already answered stray results. Recovered siblings/results sort by native timestamps with file-position ties; the active parent chain keeps its native ordering. Abandoned responses and sidechain/team/meta content are excluded. Compaction summaries remain public; `logicalParentUuid` is deliberately ignored so replaced history does not reappear.

Projection includes only public user/assistant strings or `text` blocks and inline textual `tool_result` content. Tool outcomes have role `tool` and are `failed` only when `is_error === true`. The exact standalone markers `[Request interrupted by user]` and `[Request interrupted by user for tool use]` map that user item to `interrupted`. EOF, absent stop reason and unanswered tool calls leave other messages `complete`. Other producer error/cancellation variants are unverified. Thinking/signatures, tool inputs, opaque `toolUseResult`, system/request/auth state and unknown executable payloads are never traversed or transferred. Binary/unknown public blocks produce omission diagnostics. This allowlist does not detect secrets embedded in legitimate public text.

Spilled tool output is not loaded. Inline `<persisted-output>` reference text is preserved with `unsupported-shape` and incomplete history, and arbitrary paths are never dereferenced. Subagent transcripts and full native continuation are outside this reader's scope.

Compatibility is based on official Python Agent SDK **0.2.187**, revision `3184360393a92ca8a6ec7bbbdee571afd1ce1c56`, bundling Claude Code **2.1.330**. This is a synthetic, source-derived format profile, not a provider runtime certification. A version field is optional in ordinary native files. Other well-formed producer versions emit `untested-producer` while recognized shapes stay readable; unknown record/block shapes are diagnosed and omitted. See [fixture provenance](https://github.com/rammicz/agentswitch/blob/main/test/fixtures/claude/provenance.json) and the retained [SDK license notice](claude-sdk-license.txt).

Limits reuse the Codex reader's diagnostic/context conventions: 10,000 scanned directory entries, 32 MiB per file, 1 MiB per line, 256 MiB of actual native file reads for a discovery and again for each selected history, and 100 diagnostics. `limits` can only lower these bounds. Files are streamed in at most 64 KiB chunks with every read request constrained by the remaining budget. Oversized lines are skipped without hiding later healthy records; a capped file retains complete supported records from its prefix and reports the omission. Invalid UTF-8/JSON, unsupported graph shapes, missing ancestry and cycles produce incomplete history without exposing payloads. A valid final JSON record does not need a newline; unfinished final JSON/UTF-8 is `partial-record` and can recover on the next append.

Diagnostics contain only fixed codes, controlled source categories and optional line numbers. They never include native paths, filenames, parse exception text or payload excerpts. Both the detailed result and notifications are bounded, with `diagnostic-limit` marking suppression. Discovery/root warnings go to `onDiagnostic`; detailed history diagnostics concern the selected file, so malformed sibling files do not make a healthy selected history incomplete. A history read and its discovery refresh have separate byte budgets; the notification cap covers both phases. Cut lines at metadata window edges are skipped without diagnostics.

Run `npm run check`, `npm test` and `npm pack --dry-run`. The fixture suite uses isolated synthetic roots, snapshots native bytes, guards network/process APIs and observes read budgets. Linux can additionally run the focused suite in a fresh network namespace as documented in the fixture README. No server, browser, PTY or paid model call is needed for this pure file reader; terminal/provider integration remains separate work.

The native CLI performs `discover()` once per refresh generation, then uses `readCatalogHistoryDetailed(nativeId)` to read that generation’s selected files without rediscovering all siblings for every session. It preserves quality diagnostics and file-read bounds. Ordinary `readHistoryDetailed` still rediscovers authoritatively for an explicitly selected preview/launch. The batch seam must only be used with the immediately preceding discovery generation.

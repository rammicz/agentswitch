# Bounded public-history handoffs and local archives

These offline components prepare public history for the [runtime](runtime.md). They never invoke a model, provider executable or native-history importer. The default native picker composes these APIs with exact confirmation and a durable journal; see [integration and recovery](integration.md).

## Preparation and confirmation

`createHandoffPlan({directory, source, items, currentRequest, redactions?, maxBytes?, reserveBytes?, completeness?})` in `src/handoff.ts` creates a frozen plan without filesystem reads or writes. Its `prepared` property is the complete proposed initial user prompt plus included/omitted IDs, byte count and an archive reference. `publishHandoffPlan(plan)` publishes the exact privately retained redacted snapshot under that same reference and returns the identical `prepared` object. Review the proposed content and obtain consent before publishing or launching. A cancelled preview creates no artifact. `prepareHandoff(input)` combines both operations for callers that already have consent. `buildHandoff({...input, archive})` is a pure deterministic preview with a caller-supplied reference; it does not make that reference readable.

`source` uses the picker's `{agent, id, nativeId}` identity. Input sequence is authoritative chronology. Duplicate/empty item IDs fail. The builder tries candidates once each, in tiers: latest user, latest assistant and first user; then the remaining user and assistant turns newest-first; then failed or interrupted tool output newest-first; then the remaining complete tool output newest-first. Complete tool output that is empty or whitespace-only is never sent: it stays in the archive, is listed as not included and counts as an omission. The builder includes whole items when they fit, continues after oversized items and emits selected items in original sequence. Roles, interruption/failure status and source attribution remain explicit. Empty and tool-only snapshots are supported.

The JSON prompt (`format: "agentswitch-historical-context-v2"`) holds a notice, source identity, completeness, an `origins` table, historical messages, compact omission/retrieval references and a distinct `currentRequest`. Each history item is `{id, role, text, status?, o?}`: `status` appears only when it is not `complete`, and `o` indexes the `origins` entry `{agent, context}` that attributes the item. Each distinct origin of a selected item is listed once, in order of its first appearance in the snapshot; `origins` is absent when no selected item has one. `omissions.paging` notes that the archive directory is private and outside the workspace, so a workspace-sandboxed target may need access approval to run the retrieval commands.

The full serialized UTF-8 prompt, including JSON escaping, the origins table and actual retrieval arguments, must satisfy `bytes + reserveBytes <= maxBytes`. The inclusive maximum is 16,384 bytes; callers may lower it. The actual current request is already counted. `reserveBytes` is an additional unused allowance, default zero. An empty-history envelope that cannot fit fails without publication; text is never truncated. A candidate whose exact cost without later index growth cannot fit is skipped; otherwise the envelope with it is serialized and measured, so origin table growth, index widths and the changing omission-count width are exact. This is a conservative transport budget, not a model token-capacity guarantee.

`parseHandoffPrompt(prompt)` decodes a stored prompt of either version (`-v1` repeated `status` and `origin` on every item) into `{format, currentRequest, history}` with full `status` and `origin`. Explicit fresh recovery uses it to read history from a journaled attempt whose archive was deleted.

Caller redactions are literal strings, applied before selection, preview or archive publication to public item IDs/text, source IDs and the current request. Matches become `[REDACTED]`. Reviewed plans retain only the redacted public snapshot; later mutations of caller inputs cannot change publication. The component copies only approved `id/role/text/status` fields and validated origin attribution. Use approved adapters to exclude native credential records and hidden reasoning: this component cannot infer whether arbitrary secrets were typed into legitimate public text. Review and redact those explicitly. This does not erase native histories, derived search data, earlier archives or previously returned pages.

Historical data remains inside a normal user prompt. JSON attribution does not guarantee a model will ignore every hostile instruction, but the builder does not execute commands, load referenced paths, request system authority or change provider permission flags. `completeness` is caller-supplied `complete`, `partial` or `unknown` (default); it describes only the normalized public snapshot supplied here.

## Retrieval and deletion

A handoff publishes all permitted redacted items, including omissions, in a separate dedicated archive directory. The directory must have an existing parent; its leaf is created privately if absent. Native histories and the rebuildable search cache must use different directories. The prompt includes actual argument arrays for these commands, keeping spaces and shell metacharacters unambiguous:

```sh
agentswitch archive list --directory '/private/my archives' --archive <uuid> --limit 50 --max-bytes 8192
agentswitch archive read --directory '/private/my archives' --archive <uuid> --item 7 --cursor 0 --max-bytes 8192
agentswitch archive delete --directory '/private/my archives' --archive <uuid>
```

`list` returns source, completeness and manifest entries containing ordinal, original redacted ID, role, status and whether the item was included. Continue using `nextCursor` until `null`. List cursors are item ordinals. `read` retrieves by manifest ordinal and returns metadata, text and `nextCursor`; text cursors are UTF-16 offsets at Unicode scalar boundaries. Concatenate page text verbatim to reconstruct the exact retained item, including escaped controls and emoji. A fresh process needs only the archive reference, never native history or an account.

Each JSON page defaults to 8,192 bytes and has a 65,536-byte maximum, including the CLI's trailing newline. Programmatic `listArchive`/`readArchiveItem` caps measure their JSON representation without a newline. Manifest limits default to 50, maximum 1,000. A page too small for its metadata and next entry/character fails clearly; it never returns a cursor that cannot advance. Negative, fractional, out-of-range, split-surrogate and past-end cursors fail. Archive input is bounded to 64 MiB and 100,000 items; each retrieval independently reopens and validates it. Missing/deleted references, corrupt data, unsupported versions and unsafe/inaccessible storage produce bounded errors without content echoes.

Storage uses 0700 directories and 0600 files even under a permissive umask. Existing foreign entries, symbolic-link leaves/files, nonregular files, public permissions and foreign ownership are rejected rather than chmodded or adopted. Existing parent aliases such as macOS `/var` are allowed. Safe random UUIDs are the only archive filename inputs. A private temporary file is fully written and synced, then atomically hard-linked to the exclusive final name without replacing an existing reference. The temporary name is removed and the directory synced before returning. Linux directory fsync is required; macOS tolerates unsupported directory fsync after the file has been synced. Filesystems without hard-link publication fail cleanly. Crashes can leave private `.tmp` files; these are never readable as completed archives.

Deletion removes the chosen archive and its matching temporary crash artifacts; it never recursively removes the caller's directory. Fresh API/CLI reads fail afterward. Already returned data or an in-flight read cannot be recalled, and deletion does not promise physical disk erasure. Delivery journal/lineage cleanup is the integrating caller's responsibility. There is no implicit expiry of references already sent to a target.

The integrated launcher protects a published archive with a durable per-attempt use pin before spawn. `deleteArchive` and the direct CLI refuse pinned references; a normal supervised close releases the pin, while a crashed unknown writer keeps it. Recovery uses a validated redacted snapshot through `readArchiveSnapshot`, never a stored executable launch plan.

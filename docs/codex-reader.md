# Codex reader

`CodexSessionAdapter` is a read-only programmatic implementation of `SessionAdapter`. CLI integration and provider launch are separate work. It uses Node >=22.15 built-in SQLite and experimental zstd APIs, with no runtime npm dependencies. SQLite may print Node's experimental-feature warning.

```ts
import { CodexSessionAdapter } from './adapters/index.js';
const reader = new CodexSessionAdapter({
  root: '/explicit/codex-home',
  sqliteRoot: '/explicit/sqlite-home',
  onDiagnostic: diagnostic => console.error(diagnostic.code),
});
const sessions = await reader.discover();
const history = await reader.readHistoryDetailed(sessions[0]!.nativeId);
```

Explicit `root` wins over nonempty `CODEX_HOME`, then `<home>/.codex`; `home` defaults to the OS home directory. Explicit `sqliteRoot` wins over nonempty `CODEX_SQLITE_HOME`, then the selected Codex root. `env` may replace process environment resolution for embedding/tests. Native TOML configuration, profiles, account filtering and configured `sqlite_home` are not read; pass the relevant metadata root explicitly. Only `sessions` and `archived_sessions` inside the canonical Codex root are scanned. Nested symlinks are rejected; a symlink used as the explicit home/root is canonicalized. Existing workspace paths use `realpath`; unavailable recorded paths stay absolute with a diagnostic.

`discover()` reads session headers and metadata and returns empty `messages`. Hydrate through `readHistory()` or `readHistoryDetailed()` before indexing/searching conversation text. A detailed history result contains `items`, `complete`, and history-specific `diagnostics`. Metadata/root/discovery warnings go to `onDiagnostic`. Diagnostics contain a fixed code, controlled source category and optional line number, never native JSON, error messages, transcript excerpts or native filenames. Counts are capped per operation, with a final `diagnostic-limit` marker. Operations on one reader are serialized so concurrent discovery/preview calls cannot replace each other’s catalog state. Discovery and each history read refresh selected metadata; an existing adapter sees newly completed appends and reverts.

Metadata uses `SessionMeta.id`, preserving forks that share `session_id`. SQLite `state_5.sqlite` selects the rollout and supplies explicit `name`, then `preview`/`title`. Legacy `session_index.jsonl` uses the last usable `thread_name`; a distinct SQLite title precedes it, except the native Guardian default title. A title equal to the stored first user preview is derived and yields to an indexed name. Without metadata, an unambiguous single rollout remains discoverable with a generated `Codex <id>` title and `metadataFidelity: reduced`; multiple conflicting rollouts are omitted with `ambiguous-rollout`. A known SQLite selection that is unavailable is omitted rather than replaced by an obsolete sibling. Metadata timestamps use epoch seconds or milliseconds; headers supply a fallback. `createdAt`, `historyMode`, `producerVersion` and `metadataFidelity` extend the shared Session contract without changing picker services.

Compatibility fixtures derive from official Codex **0.171.0**, source revision `ccf9be8cc458bd6b8336fe84d68d8893f2691a5e`. They test the current default `paginated` mode and `legacy` (including missing mode), plain JSONL and opt-in existing `.jsonl.zst`, active and archived roots, reverts and bounded reference lineage. Other producer versions receive `untested-producer` while recognized shapes remain readable; unknown modes are rejected. See [fixture provenance](https://github.com/rammicz/agentswitch/blob/main/test/fixtures/codex/provenance.json). This is synthetic format compatibility, not a real-provider runtime certification.

The public projection includes current completed `UserMessage`/`AgentMessage` items, public `Plan` text as assistant history and textual command, function, dynamic and MCP tool outcomes. Legacy response messages/tool outputs are canonical; mirrored user/agent events are suppressed by occurrence count, while event-only histories remain visible. Only explicit text variants are extracted. Reasoning, instructions, turn context, raw commands/arguments, unknown nested state, binary and encrypted payloads are excluded. This is a schema allowlist, not detection of arbitrary secrets inside legitimate public text. Some other public presentation items (file changes, extensions and collaborative activity) are intentionally omitted. Moderated assistant bodies are omitted.

IDs combine immutable rollout identity with the native item/call ID; records without a usable native ID use their uncompressed byte offset. Repeated reads, appends and plain/compressed representations retain IDs. Completed items remain `complete` after a later turn abort; explicit failed/declined items map to `failed`, explicit in-progress/incomplete/interrupted items to `interrupted`. Unknown explicit statuses produce an incomplete diagnostic. No prose substring determines status, and no synthetic partial assistant text is invented from a turn abort.

Reference history follows immutable rollout IDs and validates managed containment, filename/header ownership, paginated mode, exact exclusive ordinal and uncompressed byte bounds, cycles and depth. Parents are read only through their stored cutoff. Attached child display boundaries hide inherited model context; explicit subagent display ordinals are also honored. Invalid ancestry retains readable child items and returns `complete: false`. Malformed interior records are skipped with safe diagnostics, a valid final JSON record needs no newline, and incomplete final UTF-8/JSON is diagnosed until its append completes.

Default limits are 10,000 scan entries, 32 MiB encoded file, 64 MiB aggregate decoded leaf-and-ancestor input per hydrated history, 1 MiB record, depth 32, 100 diagnostics, 64 MiB per database/WAL and 256 MiB of native source-file reads per public operation, including actual header read-ahead, database/WAL snapshots and retries, the legacy index and lazy history reads. Read requests are bounded by the remaining budget before I/O; decoded output from every plain or compressed leaf/ancestor consumes the same separate history budget. If an ancestor cannot fit, the readable child is retained with incomplete history and an input-limit diagnostic. Each public history read starts a fresh decoded budget; metadata-only header discovery does not spend the hydrated-history budget. `limits` can lower these values. Caps produce diagnostics; they do not imply complete history. Compressed discovery bounds encoded bytes and stops decoding after the header; full lazy reads cap aggregate decoded output across the lineage. No compressed source is materialized on disk.

SQLite never opens the native database. It copies DB and any WAL through read-only file handles into a private 0700 temporary directory (0600 files), compares source identity/size/nanosecond change stamps before and after, retries changing copies at most three times, and queries/recoveries only the private copy. Missing, incompatible, unreadable or unstable metadata yields reduced-fidelity diagnostics. Native shm is neither opened nor copied; private SQLite creates its own sidecars. Fixtures cover committed WAL-only changes, a reserved writer lock and injected continuously changing stat stamps and compare every native file/directory and byte before/after. This bounded stable-copy check is not a filesystem snapshot transaction against adversarial file replacement; a continuously changing writer can require a later retry. No native CLI, config initialization, account access, credential copying, network or model call is used.

Run `npm run check`, `npm test` and `npm pack --dry-run`. Direct adapter tests create isolated temporary homes, database/WAL and compressed fixtures. The offline subprocess denies network/process APIs and places poisoned provider executables on PATH. CLI PTY tests exercise the existing demo separately. CI includes the exact minimum Node 22.15.0 on Linux and macOS. Personal histories and paid provider smoke tests are outside default verification.
